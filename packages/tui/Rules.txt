STEWARD TUI — MASTER RULES (stitchable)
═══════════════════════════════════════════════════════════════════════════════
Version: permanent. This file is the single source of truth for all work done
under packages/tui/ (stitchable). It is not a "guideline" or a "best practice doc" —
it is the contract that keeps this package maintainable and architecturally isolated.
Read it entirely before making any edit. If a rule seems wrong, change the rule
explicitly in its own commit with a written rationale; do not quietly route around it.

═══════════════════════════════════════════════════════════════════════════════
WHY THIS TUI IS CUSTOM AND WHY THAT MATTERS
═══════════════════════════════════════════════════════════════════════════════
Steward does NOT use Ink, Blessed, React, or any other third-party TUI framework.
It has its own from-scratch terminal rendering engine (`stitchable`). This is a
deliberate choice: frameworks bring reconcilers, fibers, synthetic event loops,
and large dependency trees that interfere with Mode 2026 Synchronized Output
(the protocol that prevents flicker on rapid updates).

Key facts every contributor must internalize:

  1. There is NO virtual DOM, NO reconciler, NO fiber. `setState()` on a
     Component sets `_dirty = true` and calls `engine.requestFrame()`, which
     schedules a microtask-based debounced re-render. The next render pass
     calls `component.getLines(width)`, which invokes `renderWithCursor(width)`
     if dirty, caches the result, and returns the cached lines on subsequent
     calls within the same frame.

  2. The terminal is written to ONCE per frame via Mode 2026 Synchronized
     Output (CSI ?2026h / CSI ?2026l). Do not call process.stdout.write()
     yourself from any component or primitive — you will break sync output.

  3. Line ownership is absolute. TerminalEngine owns the entire screen. No
     component "owns" a row number — the engine assigns rows by summing
     component line counts at render time. Never hard-code a row offset anywhere.

  4. The render pipeline is:
       Component.renderWithCursor(width)
         → string[] lines + optional cursor
         → TerminalEngine passes lines to DocumentTree / HistoryStore
         → StateRenderer diffs against last frame (FrameBuffer)
         → ScreenBuffer emits only changed cells as ANSI bytes
     Do not short-circuit any step of this pipeline.

  5. Width is always passed in. Never call process.stdout.columns from inside
     render() or renderWithCursor(). Width is injected by the engine at render
     time and the component must use it.

  6. Input dispatch is strictly typed. All listeners receive `InputEvent`
     (discriminated union of key and bracketed paste). Handlers never inspect
     raw stream bytes or call process.stdin directly.

RULE 1 — HARD BOUNDARIES
═══════════════════════════════════════════════════════════════════════════════
`packages/tui/` (`stitchable`) is a zero-dependency, domain-blind package.
It knows NOTHING about Steward agents, LLM providers, chat sessions, or CLI commands.

═══════════════════════════════════════════════════════════════════════════════
RULE 2 — LAYER 0 IS FROZEN
═══════════════════════════════════════════════════════════════════════════════
Files in Layer 0 (engine/, layout/, terminal/) may be edited ONLY for one of these
reasons — label your PR/commit with the reason letter:

  A) A new terminal capability or escape sequence requires support (e.g. a
     new resize signal variant, Mode 2026 enter/exit adjustment).

  B) A genuine, reproducible bug in cell diffing, line wrapping math, scroll
     arithmetic, or cursor placement demonstrable with plain, unstyled text.

  C) A measured performance regression in the render loop itself.

  D) Input-dispatch contract/bug: terminal event to InputEvent conversion
     (`toInputEvent`) and bracketed paste robustness.

═══════════════════════════════════════════════════════════════════════════════
RULE 3 — NO CONTENT-SNIFFING IN LAYOUT CODE
═══════════════════════════════════════════════════════════════════════════════
`packages/tui/src/text/` and `packages/tui/src/engine/layout.ts` must NEVER branch
on what the text IS. Callers pass explicit numeric indent and wrapping parameters.

═══════════════════════════════════════════════════════════════════════════════
RULE 4 — OVERFLOW AND TRUNCATION ARE TWO BOOLEANS
═══════════════════════════════════════════════════════════════════════════════
The component overflow contract is:

  wrap: boolean      // true  = soft-wrap across rows
                     // false = single-row output only
  clip: boolean      // true  = hard truncate to available width
                     // false = allow overflow
  ellipsis?: boolean // only valid when clip === true; appends "…"

All components declare these three overrides explicitly at the top of the class:
  override wrap = false;
  override clip = true;
  override ellipsis = false;

═══════════════════════════════════════════════════════════════════════════════
RULE 5 — CURSOR POSITION IS DERIVED IN ONE PASS, NEVER HAND-COMPUTED
═══════════════════════════════════════════════════════════════════════════════
The single-pass cursor invariant:
  renderWithCursor(width?: number): {
    lines: string[];
    cursor: { logicalLineIndex: number; characterOffsetWithinLine: number } | null;
  }
Both lines and cursor are produced in the same execution pass.

═══════════════════════════════════════════════════════════════════════════════
RULE 6 — JSX IN STITCHABLE
═══════════════════════════════════════════════════════════════════════════════
  • JSX does NOT render to React. It renders to BoxElement/TextElement.
  • Intrinsic elements are <Box> and <Text>.
  • Fragments are supported via Symbol.for('steward.fragment').
  • Function components and Class components are supported.

═══════════════════════════════════════════════════════════════════════════════
RULE 7 — WIDTH IS INJECTED, NEVER READ FROM PROCESS
═══════════════════════════════════════════════════════════════════════════════
Components must accept width as a parameter from the engine and use it.
Never consult process.stdout.columns inside rendering or layout calculation.

═══════════════════════════════════════════════════════════════════════════════
RULE 8 — COMPONENT LIFECYCLE & INPUT EVENT CONTRACT
═══════════════════════════════════════════════════════════════════════════════
  • `componentDidMount()` is where input listeners are registered via
    `engine.addInputListener((ev: InputEvent) => boolean | void)`. Always store
    and call the cleanup callback in `componentWillUnmount()`.
  • `componentWillUnmount()` must clear ALL timers.
  • All listeners receive `InputEvent` (`isPaste` is true for bracketed paste;
    key modifiers `ctrl`, `shift`, `meta` are cleanly typed).
  • Components never read `process.stdin` or call an input parser directly.

═══════════════════════════════════════════════════════════════════════════════
RULE 9 — TEST HARNESS USES MEMORYIO
═══════════════════════════════════════════════════════════════════════════════
  • All headless and characterization tests run over `memoryIO()` without
    reading or writing `process.stdout` or `process.stdin`.
  • Timers and input events are deterministically flushed via `engine.flushInput()`.
  • Visual snapshots are byte-exact and verified with `assertGoldenMatch`.

═══════════════════════════════════════════════════════════════════════════════
RULE 10 — PROPOSING A STRUCTURAL CHANGE
═══════════════════════════════════════════════════════════════════════════════
1. Write down the specific structural gap in the current architecture.
2. Confirm the gap cannot be addressed in Layer 1 elements.
3. Describe the change and rationale in a commit referencing this file.
4. Update this file in the same commit as the structural change.
