# Package Name (`@steward/agent`)

Zero-dependency, multi-step agent turn loop, streaming lifecycle events, and core contracts for Steward.

---

## 1. Overview & Architecture

### High-Level Mental Model
`@steward/agent` is the core agent execution engine of Steward. It provides a pure, deterministic, multi-step turn loop (`runAgentLoop`) that orchestrates LLM streaming, reasoning extraction, sequential tool execution, token usage accumulation, and fine-grained event telemetry.

It is strictly decoupled from concrete LLM wire transports, file system operations, and terminal UI components. The loop interacts with model streaming and tool invocation solely through pure functional interfaces (`StreamFn`, `executeTool`, and `AgentEventListener`).

### Architecture & Data Flow (ASCII Diagram)

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          runAgentLoop Turn Flow                             │
└─────────────────────────────────────────────────────────────────────────────┘

 Caller / Orchestrator (e.g., CLI Turn Runner)
       │
       ├─── runAgentLoop({ messages, stream, tools, executeTool, signal, onEvent })
       │
       ▼
 ┌────────────────────────────────────────────────────────────────────────────┐
 │  Step Loop (step = 1 ... maxSteps [default 50])                            │
 │                                                                            │
 │  1. Stream Request: stream({ messages, tools, effort, temperature })      │
 │        │                                                                   │
 │        ├───► AsyncIterable<StreamEvent>                                    │
 │        │       ├── text-delta ─────────────► accumulate text & emit update │
 │        │       ├── reasoning-delta ────────► accumulate thought & update   │
 │        │       ├── tool-call-start / delta ► emit message-update           │
 │        │       ├── tool-call-end ──────────► collect completed call IDs   │
 │        │       └── retry ──────────────────► emit retry event              │
 │        │                                                                   │
 │        └───► stream.result() ──► AssistantMessage + TokenUsage             │
 │                                                                            │
 │  2. Assistant Message Sanitization:                                        │
 │     Filter incomplete/orphaned tool calls if stream was aborted/errored.   │
 │                                                                            │
 │  3. Step Decision:                                                         │
 │     ├─ Stream Error? ──────────────► Set stopReason='error'|'aborted' & END│
 │     ├─ Zero Tool Calls? ───────────► Set stopReason='natural' & END        │
 │     └─ Hit maxSteps with Tools? ───► Set stopReason='step-limit' & END     │
 │                                                                            │
 │  4. Sequential Tool Execution (in model-defined order):                    │
 │     For each tool call:                                                    │
 │        ├─ If aborted ──────────────► Synthesize error ToolResult           │
 │        ├─ Else executeTool(call) ──► Invoke tool callback with AbortSignal │
 │        └─ Emit tool-execution-start / tool-execution-end                   │
 │                                                                            │
 │  5. History Append & Invariant Guarantee:                                  │
 │     Append 1:1 paired ToolMessage ({ role: 'tool', content: [...] })       │
 │     Feed updated history into step + 1                                     │
 └────────────────────────────────────────────────────────────────────────────┘
       │
       ▼
 ┌────────────────────────────────────────────────────────────────────────────┐
 │ Return AgentRunResult:                                                     │
 │ - newMessages: Message[] (all assistant and tool messages generated)       │
 │ - stopReason: 'natural' | 'step-limit' | 'aborted' | 'error'               │
 │ - usage: TokenUsage (summed input, output, cache, reasoning tokens)        │
 │ - text / reasoning / toolResults / durationMs                              │
 └────────────────────────────────────────────────────────────────────────────┘
```

### Key Technical Invariants

1. **Zero External Runtime Dependencies:** Zero third-party runtime dependencies; pure TypeScript and web standard primitives (`AbortSignal`, `performance.now()`, `AsyncIterable`).
2. **1:1 Tool-Call to Tool-Result Pairing Invariant:** Every tool call generated by the model is guaranteed to have a corresponding `ToolResultContent` entry in the subsequent tool message. If execution is aborted or fails, synthetic error results are automatically produced so conversation history remains structurally valid.
3. **Sequential Execution Order:** Multi-tool batches emitted by the model are executed strictly sequentially in the exact order generated by the model.
4. **Orphaned Tool Call Pruning:** If a stream aborts or errors mid-generation before emitting `tool-call-end`, partial/orphaned tool-call content blocks are sanitized from the assistant message before saving to history.
5. **Resilient Event Dispatch:** All callbacks dispatched to `onEvent` are wrapped in exception guards; listener crashes (e.g. TUI rendering errors) never abort or corrupt the agent loop.
6. **Precise Token Accounting:** Token usage across all intermediate steps (input, output, reasoning, cache read, cache write) is accumulated deterministically.

## 2. Quick Start & Basic Usage

```typescript
import {
  runAgentLoop,
  type Message,
  type StreamFn,
  type ToolCallContent,
  type ToolResult,
  type ToolSpec,
} from '@steward/agent';

// 1. Define conversation history
const messages: Message[] = [
  { role: 'user', content: 'What is the current time and check status?' },
];

// 2. Define available tools
const tools: ToolSpec[] = [
  {
    name: 'get_time',
    description: 'Get current ISO time',
    inputSchema: { type: 'object', properties: {} },
  },
];

// 3. Provide tool execution handler
const executeTool = async (call: ToolCallContent, signal: AbortSignal): Promise<ToolResult> => {
  if (call.name === 'get_time') {
    return {
      id: call.id,
      name: call.name,
      args: call.arguments,
      result: { time: new Date().toISOString() },
      isError: false,
    };
  }
  return {
    id: call.id,
    name: call.name,
    args: call.arguments,
    result: `Unknown tool: ${call.name}`,
    isError: true,
  };
};

// 4. Run the multi-step loop
const result = await runAgentLoop({
  messages,
  tools,
  stream: myModelStreamFn, // StreamFn implementation from inference provider
  executeTool,
  maxSteps: 10,
  onEvent: (event) => {
    if (event.type === 'message-update' && event.streamEvent.type === 'text-delta') {
      process.stdout.write(event.streamEvent.delta);
    }
  },
});

console.log(`Finished with stop reason: ${result.stopReason}`);
console.log(`Total tokens used: ${result.usage.total}`);
```

## 3. Core Concepts & Mental Model

### Message Hierarchy (`Message`)
The message model supports rich multimodal content and tool calling:
- **`SystemMessage`**: `{ role: 'system', content: string }`
- **`UserMessage`**: `{ role: 'user', content: string | readonly TextContent[] }`
- **`AssistantMessage`**: `{ role: 'assistant', content: readonly AssistantContent[], meta?: Record<string, unknown> }`
  - `TextContent`: `{ type: 'text', text: string, textSignature?: string }`
  - `ThinkingContent`: `{ type: 'thinking', thinking: string, thinkingSignature?: string, redacted?: boolean }`
  - `ToolCallContent`: `{ type: 'tool-call', id: string, name: string, arguments: Record<string, unknown>, thoughtSignature?: string }`
- **`ToolMessage`**: `{ role: 'tool', content: readonly ToolResultContent[] }`
  - `ToolResultContent`: `{ type: 'tool-result', toolCallId: string, toolName: string, output: JsonValue, isError?: boolean }`

### Stop Reason Classification (`AgentRunStopReason`)
- `'natural'`: The model produced a regular text response without requesting further tool calls, or completed all requested tools on a step and gave a final response.
- `'step-limit'`: The loop reached `maxSteps` (default: 50) while the model was still requesting additional tool calls.
- `'aborted'`: Execution was cancelled via `AbortSignal` either during streaming or tool execution.
- `'error'`: An unrecoverable streaming or transport error occurred.


#### `TokenUsage`
```typescript
export interface TokenUsage {
  input?: number;
  output?: number;
  cacheRead?: number;
  cacheWrite?: number;
  reasoning?: number;
  total?: number;
  cost?: { input: number; output: number; cacheRead?: number; cacheWrite?: number; total: number };
}
```

#### `StreamEvent`
Events yielded by the `ModelStream` async iterator:
```typescript
export type StreamEvent =
  | { type: 'text-delta'; delta: string }
  | { type: 'reasoning-delta'; delta: string }
  | { type: 'tool-call-start'; id: string; name: string }
  | { type: 'tool-call-delta'; id: string; delta: string }
  | { type: 'tool-call-end'; toolCall: ToolCallContent }
  | { type: 'retry'; attempt: number; maxAttempts: number; delayMs: number; error: StreamError }
  | { type: 'done'; message: AssistantMessage; usage: TokenUsage; finishReason: string }
  | { type: 'error'; error: StreamError; partial?: AssistantMessage };
```

#### `ModelStream` & `StreamFn`
```typescript
export interface ModelStream extends AsyncIterable<StreamEvent> {
  result(): Promise<StreamResult>;
}

export type StreamFn = (req: StreamRequest) => ModelStream;
```

#### `AgentRunResult`
```typescript
export interface AgentRunResult {
  newMessages: Message[];
  stopReason: AgentRunStopReason;
  usage: TokenUsage;
  finishReason: string;
  error?: StreamError;
  durationMs: number;
  startedAt: string;
  finishedAt: string;
  text: string;
  reasoning?: string;
  toolResults: readonly ToolResult[];
}
```

## 5. Functions & Lifecycle Events Reference

### `runAgentLoop(options: RunAgentLoopOptions): Promise<AgentRunResult>`
Executes the full multi-step agent turn.

#### `RunAgentLoopOptions`
| Property | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `messages` | `Message[]` | Required | Initial message history (not mutated; returns new entries in `newMessages`). |
| `stream` | `StreamFn` | Required | Function returning a `ModelStream` for model inference. |
| `executeTool` | `(call, signal) => Promise<ToolResult>` | Required | Handler that executes a tool call and returns its outcome. |
| `tools` | `readonly ToolSpec[]` | `undefined` | Optional catalog of tool schemas available to the model. |
| `maxSteps` | `number` | `50` (`DEFAULT_SAFETY_STEP_CEILING`) | Maximum iterative model-tool steps allowed in one turn. |
| `effort` | `ReasoningEffort` | `undefined` | Reasoning effort parameter passed to model inference. |
| `temperature` | `number` | `undefined` | Temperature setting for model sampling. |
| `signal` | `AbortSignal` | `undefined` | AbortSignal to cleanly cancel streaming or tool execution. |
| `onEvent` | `AgentEventListener` | `undefined` | Real-time event listener for streaming UI updates. |

### `AgentEvent` Catalog (`src/events.ts`)

| Event Type | Properties | When Emitted |
| :--- | :--- | :--- |
| `agent-start` | `{}` | Beginning of the turn before any step execution. |
| `turn-start` | `{ step: number }` | Beginning of step `N` (1-indexed). |
| `message-start` | `{ message: Message }` | When stream begins receiving assistant message chunks. |
| `message-update` | `{ message: Message, streamEvent: StreamEvent }` | On every streamed text, reasoning, or tool-call delta. |
| `message-end` | `{ message: Message }` | When the assistant message stream completes for the current step. |
| `tool-execution-start` | `{ toolCall: ToolCallContent }` | Immediately before `executeTool()` is invoked for a tool call. |
| `tool-execution-update` | `{ toolCallId: string, update: unknown }` | Progress update during long-running tool execution. |
| `tool-execution-end` | `{ toolCall: ToolCallContent, result: ToolResult }` | After `executeTool()` resolves or rejects. |
| `turn-end` | `{ message: Message, toolResults: readonly ToolResult[], usage?: TokenUsage }` | Concluding a step with its message and tool results. |
| `retry` | `{ attempt, maxAttempts, delayMs, error }` | When inference provider triggers an automatic backoff retry. |
| `agent-end` | `{ result: AgentRunResult }` | Final event dispatched when turn concludes. |

### Helper Functions

#### `accumulateTokenUsage(current: TokenUsage, delta?: TokenUsage): TokenUsage`
Safely sums token metrics (input, output, reasoning, cache read, cache write, total).

#### `sanitizeAssistantMessage(message: AssistantMessage, completedCallIds: Set<string>): AssistantMessage`
Removes partial/orphaned `tool-call` content blocks that did not receive a corresponding `tool-call-end` event.

## 6. Advanced Patterns & Practical Guides

### Handling User Cancellation & Abort
When `signal.abort()` is triggered during a turn:
1. Active LLM stream iteration terminates immediately.
2. Any unexecuted tool calls in the current step receive synthesized error results with message `"Aborted by user"`.
3. `stopReason` is set to `'aborted'`.
4. History is preserved cleanly without corrupting tool call / result pairs.

### Capturing Tool Errors Without Crashing the Turn
If `executeTool` throws an unhandled error, `runAgentLoop` catches the exception, creates an error `ToolResult` (`isError: true`), emits `tool-execution-end`, and feeds the error back to the model in the next step so the LLM can explain or correct its mistake.

## 7. Real-World Gotchas, Tips & Edge Cases

1. **Step-Limit vs Natural Stop:**
   If step `maxSteps` produces only plain text without requesting tool calls, `stopReason` is `'natural'`. It is only marked `'step-limit'` if the model was actively attempting to continue the loop with more tool calls on the final step.
2. **Listener Exception Isolation:**
   `onEvent` callbacks are wrapped in a try/catch block. If a UI event handler throws an error, the agent loop logs/ignores the listener error and continues execution.
3. **Empty Text Streams:**
   If a model outputs only tool calls without leading text, `accumulatedText` remains `""` and the assistant message content contains only the `ToolCallContent` blocks.
4. **Token Usage Accumulation:**
   Provider streams may report partial or step-specific usage. `accumulateTokenUsage` ensures total token counts are monotonically added across all steps.
